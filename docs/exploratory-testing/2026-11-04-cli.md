# CLI exploratory testing, 2026-11-04

## Setup

Tested `b943e98d257c675a4b2f3ffd9d1306118a31b2ca`, the `origin/main` tip, in a fresh Linux amd64 worktree. The host had no GHC, so the pass used `haskell:9.4.3`, the version in the Dockerfile. The container had no network, used a worktree-local home and data directory, and ran as the host user. Its image digest was `sha256:6d5883d5e5382fd6a8c51eb32460a7eb94fbe5ed6b44b98b9194437bc35d0bf8`.

The project has no dependency lockfile. `make build` uses GHC's bundled `base`, `time`, and `process` packages and needs no dependency installation. This pass did not install the Cabal mutation-test dependencies. `make build` and `make test` passed. The [terminal transcript](2026-11-04-cli-output.txt) records commands, exit codes, diagnostics, and file contents. Each journey started with fresh data.

## Journeys

1. **Measure commands and preserve their effects.** `avg 'printf x >> count' 3` printed an average and left three bytes. A pipeline selected `b` and appended it to a file twice. The file contained two `b` lines. Both commands exited zero.
2. **Correct invalid input.** Missing arguments, a malformed count, zero, and a negative count exited nonzero with diagnostics. A corrected count of two printed an average and left two bytes. The oversized value from [issue #3](https://github.com/jonbaldie/avg/issues/3) was rejected before it wrote a file. That issue is closed as fixed by [PR #7](https://github.com/jonbaldie/avg/pull/7).
3. **Stop on a failed command and retry.** A command that wrote one byte and exited 7 stopped after one iteration in two fresh replays. A retry with a successful command wrote two bytes and printed an average. A second variation failed on its second iteration. Two fresh replays each left two bytes and returned an error without an average. A missing command, explicit exit 127, and shell termination by SIGTERM also returned nonzero.

## Findings and observations

No new bug was confirmed, so no new issue was filed. The previous oversized-count finding did not reproduce on this commit.

An empty command string exited nonzero with `avg: system: invalid argument (null command)`, rather than the CLI's own diagnostic. The README does not specify whether an empty command string is valid, so this is an unresolved usability observation rather than a confirmed bug. It was observed once and was not replayed.

The missing-command variation printed `/bin/sh: ... Permission denied` before reporting exit code 127. The container's shell and `PATH` may affect that diagnostic. The documented nonzero failure behavior held, but the reason for the shell's wording was not investigated.

No server, browser, port, or volume was started.
